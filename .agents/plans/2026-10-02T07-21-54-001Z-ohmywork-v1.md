## 1. 已完成的技术核验与采用路线

### 1.1 本机现状

当前为 Windows 11 x64，VS C++ Build Tools 已安装，普通 shell 尚未载入 MSVC 环境。当前 PATH 和用户标准 `.cargo/bin` 未发现 Rust/Cargo，CMake/clang-cl 也未在 PATH 中发现。执行前先检查非标准安装位置，不直接覆盖用户环境。

性能机：Ultra 7 255HX、约32GB、Intel Graphics + RTX5070Ti Laptop、NVMe、2560×1600/60Hz。此处不是构建/性能实测结果。

### 1.2 不再留成“候选”的主路线

| 职责 | 本计划采用 | 不采用 |
|---|---|---|
| UI | `gpui-kit = =0.7.0`（默认 component/assets），通过其配套 GPUI 原生 Windows 路线 | 直接拼装裸 GPUI 应用、Electron、WebView、照搬 Zed 全应用 |
| 编辑 | 自建源片段保真的文档模型 + GPUI Kit 标准控件；仅自定义编辑表面使用其重导出的 GPUI Element/EntityInputHandler | 把 GPUI Kit 的源码 Editor/Markdown renderer 当成无损可视化编辑器 |
| Markdown | Comrak 0.55.0，默认特性关闭，仅开标准 GFM解析选项 | 每次保存用 formatter 重排整篇 |
| 文本缓冲 | Ropey 1.6 系列 + 自有 byte/source map | 每个按键复制整份文件 |
| 索引 | rusqlite 0.40.2 bundled SQLite；一个全局数据库 | 为每项目建库、引入外部搜索服务 |
| 搜索 | FTS5 trigram + 专用短词 unigram/bigram token 索引 | 只用英文 tokenizer，或短中文直接全库扫 |
| 并发 | GPUI Kit/GPUI 主线程 + Tokio 两个 I/O线程 + 两个解析工作线程 + SQLite专用线程 | UI线程阻塞 I/O，无界任务生成 |
| 文件规则 | ignore::gitignore::GitignoreBuilder 显式只添加 .ohmyworkignore | 使用自动读取Git配置的默认 WalkBuilder |
| 文件事件 | notify + 内容指纹/文件身份核对 | 静默忽略一段时间内的全部 watcher 事件 |
| Windows API | windows crate，安全替换/文件身份/进程与系统打开均封装 | shell 拼接文本、写盘失败退回原地覆盖 |
| PDF | pdfium-render 0.9.4 + 固定 PDFium 7881 Windows x64 非V8二进制，内部预览子进程 | 在UI线程渲染、依赖用户安装PDF软件、加载cwd里的DLL |
| 图片 | image 0.25，PNG/JPEG/WebP/GIF/BMP；GIF首帧只读预览 | 首版动画播放器、OCR |
| 配置 | serde/serde_json；jsonc-parser 只用于 JSONC 配置 | 自行用正则删除注释 |
| 测试 | Rust单元/集成、proptest、GPUI Kit `test-support`、假RPC程序、PowerShell端到端脚本 | 单元测试依赖真实Pi模型 |
| 分发 | NSIS 当前用户安装，RequestExecutionLevel user | 自动更新、安装时联网下载Pi |

固定 crates.io 稳定版 `gpui-kit = =0.7.0`，不写宽泛的 `0.7`。该版本自身精确固定配套的 `gpui-pre`、`gpui-pre-platform` 等快照为 `=0.3.7`；应用只直接依赖 `gpui-kit`，通过 `gpui_kit::*`、`gpui_kit::component`、`gpui_kit::base`、`gpui_kit::assets` 和 `gpui_kit::platform` 使用能力，不再直接声明或覆盖 `gpui`/`gpui_platform`。生产默认启用 component/assets；`test-support` 只在测试依赖启用；tree-sitter、shell、webview 等未用 feature 不开启。提交 `Cargo.lock` 并使用 `--locked`，升级 Kit 时整体重跑平台、输入、布局、主题和无障碍测试。

固定 Rust 1.98.1；GPUI Kit 文档当前基线是Rust 1.92以上，Windows还要求VS 2022 C++ workload、MSVC SDK和可执行的CMake。仅安装Windows MSVC目标和fmt/clippy。以上版本有发布元数据依据，但还未完成本机编译；若固定组合构建失败，记录具体错误并修订锁定版本，不静默追踪main或单独替换某个GPUI快照。

GPUI Kit、gpui-base和gpui-component为Apache-2.0；不能据此假定所有示例内容或传递资产均可随意复制。只启用所需feature，生成传递依赖与资源许可证清单。

### 1.3 源码核验得到的关键事实

- 应用入口使用 `gpui_kit::application()` 注册资源，在打开窗口前调用一次 `gpui_kit::init(cx)`，并用 `gpui_kit::open_window(...)` 自动挂载管理Dialog/通知等浮层的 `Root`。
- 标准输入、按钮、对话框、Tree、VirtualList、DatePicker、Command和Dock优先用GPUI Kit组件；状态保存在长期存在的Entity中，不能在每次render时重建输入状态。
- GPUI Kit重导出的GPUI `EntityInputHandler` 仍提供选区、UTF-16替换、marked text、字符位置与bounds接口。源片段保真的可视化Markdown编辑器没有现成替代，仍需自定义Element；Kit的源码Editor/TextView只用于其适配场景，不能成为文档事实来源。
- GPUI Kit标准组件已有AccessKit语义和UI测试支持，但自定义编辑器、画布和自绘节点仍须提供稳定Element ID、TextInput/TextRun、状态、焦点与可访问动作；不能把“用了Kit”当成自动满足WCAG。
- Comrak是GFM解析器，节点有 `Sourcepos`；默认列按UTF-8字节计数，不能当Unicode字符下标。TaskItem有checkbox符号源位置。解析器不保证原样序列化。
- SQLite trigram的MATCH不匹配少于三个Unicode字符的查询，所以必须补短词路径。
- PDFium不保证线程安全，wrapper的锁只是串行化调用；采用专用工作进程内单线程，不创建任意并行PDF调用。

## 3. 运行时所有权：谁持有什么

### 3.1 UI拥有的状态

`AppState` 包含：

- `WorkspaceState { root, workspace_uuid }`，仅一个。
- `Documents: HashMap<DocumentKey, Entity<DocumentSession>>`，所有Pane引用同一实体。
- `PaneTree`、`HomeCanvas`、主题快照、语言、命令注册表。
- `PiPanelState`，保存显示状态和明确用户选择，不保存Agent策略。

`DocumentKey` 以解析后的实际文件路径/别名表去重；不要只用Windows File ID作为文档永恒身份，因为原子替换会改变File ID。

### 3.2 后台服务

- `LocalService` 接收文件读取/扫描/安全提交请求。
- `IndexService` 在一个专用线程持有SQLite连接，WAL，foreign_keys开启，忙等待有界；慢搜索有取消标记。
- `ParsePool` 固定2线程，按文档只保留最新待解析代次。
- `PiClient` 在Tokio运行I/O，不把Runtime::block_on放UI。
- `PreviewClient` 管理单个按需启动的预览工作进程。

通道：普通请求队列初值256项、文件事件积累成按路径去重的脏集合；有界队列满时合并/背压，不丢失保存操作。UI接收结果同时检查 `request_id/doc_rev/query_generation`，旧结果直接弃用。

流式Pi文本在后台完整消费、保留当前消息累积值，UI最多按一帧频率取新快照；只合并绘制通知，不丢失协议消息或请求。

### 3.3 不建立第二份内容事实来源

- Markdown文件：持久正文与Task事实来源。
- 内存 `DocumentSession`：尚未Ctrl+S的编辑，只在当前进程存活。
- SQLite：可重建搜索/Task投影。
- JSON应用状态：布局、设置、导入主题选择，不含未保存正文或Pi transcript。

```text
  logs/                          # 本地脱敏日志

```

`.ohmywork/id` 采用UTF-8一行UUID加换行，使用create-new方式避免覆盖既有ID；内容非法就诊断，不悄悄替换。便携开关状态可由 `.ohmywork/portable.json` 明确表示；启用后 `.ohmywork/ui-state.json` 为布局/置顶的权威源，本机root路径、Pi命令、日志、索引、缓存和主题副本仍留LocalAppData。切换模式先复制并验证，再更新模式标记；失败维持原权威源，不双写两边。

本计划提出的首次启动流程：选择目录 → 展示三个分区用途及将创建的路径 → 确认 → 只创建缺失目录和ID。已有同名文件、只读目录或创建失败则阻止完成设置，保留已存在内容；不自动移动笔记。

默认ignore仅排除 `.git/` 与 `.ohmywork/` 等明确内部目录，不读取任何Git规则，也不默认屏蔽用户 `.pi/`。完整默认列表作为fixture固定；用户文件只能通过 `.ohmyworkignore` 调整。

应用设置/布局使用临时文件+替换，版本不支持时保留原文件并提供诊断；不以重建索引为由删除持久设置。

## 5. 文档模型与可视化编辑算法

### 5.1 结构契约（Rust结构示意，不是已编译代码）

```rust
struct DocumentSession {
    disk: DiskSnapshot,           // 最近确认的已提交原文
    working: WorkingDocument,     // 包含未保存编辑
    revision: u64,
    history: EditHistory,
    commit: Option<CommitInFlight>,
}
struct DiskSnapshot {
    bytes: Arc<[u8]>,
    text: Rope,
    version: DiskVersion,
    tree: Arc<LosslessTree>,
}
struct DiskVersion { hash: [u8; 32], len: u64, file_identity: Option<WinFileIdentity> }
struct Node {
    id: NodeId,                   // 只在当前会话稳定，不写入Markdown
    kind: NodeKind,
    origin: Option<SourceSlice>,  // UTF-8 byte range，含原始语法
    children: Vec<NodeId>,
    dirty: DirtyFlags,
}
struct TaskFields {
    completed: bool,
    start: Option<NaiveDate>,
    due: Option<NaiveDate>,
    priority: Option<u8>,         // 1..9，9最高
    field_spans: FieldSpans,
}
```

打开时记录UTF-8 BOM与LF/CRLF；不做无提示编码转换。V1计划只编辑UTF-8/UTF-8 BOM，其他编码显示只读诊断并允许外部打开，不能冒充已解码成功；这是需要随本计划批准的格式边界。

### 5.2 从原文建立 LosslessTree

1. 建 `line_start_bytes`，解析时保持Comrak字节列默认值，不开启sourcepos_chars。
2. `parse_document(Arena, source, Options)`：只打开table、tasklist、strikethrough、autolink；footnotes/wiki/frontmatter等额外扩展关闭。
3. 将Arena节点转换为自有owned节点，再释放Arena，避免把带生命周期树塞进跨线程/GPUI实体。
4. 将1-based起止行列转成半开UTF-8范围。对空节点、生成节点及不可靠位置显式标记，不能机械对所有end加1。
5. 每个容器保存子节点间的原始间隙、分隔符、缩进、换行以及原始子片段，所有源字节都有归属。
6. 原始HTML、未知安全边界和不能解释的片段形成Raw节点，源字节不执行、不改内部。
7. `TaskItem.symbol_sourcepos` 定位checkbox。只在Task语义文本范围中扫描元数据，不解析代码片段里的伪字段。

选Comrak的原因是GFM语义和源位置齐备；源位置不等于无损CST，所以源间隙记录与格式保真层必须自建并测试。

### 5.3 编辑事务，不直接操作Markdown字符串UI

支持的操作从小到大实现：

```text
InsertText / DeleteText / ReplaceSelection
SplitBlock / JoinBlocks
ToggleMark(Bold|Italic|Strike|Code)
SetBlockKind(Paragraph|Heading|Quote|Code)
InsertList / IndentItem / OutdentItem
InsertTable / InsertRow / DeleteRow / EditCell
SetLink / SetTaskField / MoveNode / DeleteNode
```

普通输入是可视化文本，序列化时转义必要Markdown字符；格式通过工具栏/命令完成。普通粘贴为文字，另提供明确“粘贴Markdown”命令解析结构，避免把任意HTML剪贴板当作可执行富文本。

`EditTransaction` 记录NodeId与语义操作、选择前后值，不能只记录旧行号。结构移动保留NodeId；删除标记tombstone；外部重载产生全新代次并清空该文件撤销历史。

### 5.4 最小序列化

`plan_source_patches(base, working) -> Vec<TextPatch>`：

- 未改节点直接复用SourceSlice，包括未知字段/空白。
- 文本叶子变化，只序列化叶子或最小受影响内联容器。
- 列表缩进/表格列数等结构变化，扩大到受影响容器；其中未变子片段能复用则复用。
- 切勿承诺每次只改几个字节：必要结构边界内可重排，但不碰无关段落。
- Patch带 `range + expected_hash + replacement`，去除重叠后按倒序应用到基线。
- 生成结果再次解析，确认语义树符合编辑意图；若不一致，阻止保存并报告，不能改用全文formatter兜底。

### 5.5 GPUI Kit可视化表面

- 工具栏、按钮、菜单、Dialog、Tooltip、滚动容器等直接使用GPUI Kit组件；不重复实现Kit已有的键盘、焦点、主题和AccessKit行为。
- `EditorView` 是Entity，保存视口/选择/marked range，不独占文档内容。
- 无损可视化Markdown仍由自有 `EditorElement` 实现request_layout/prepaint/paint；块高度缓存，二分查可见块，只排版可见区域和上下缓冲。不能用Kit的源码Editor或TextView替代该模型。
- 文字使用GPUI Kit重导出的GPUI text system shaping，布局缓存键为NodeId、内容版本、可用宽度、字体与主题版本。
- `EntityInputHandler` 的UTF-16范围先转视觉文本位置，再映射NodeId/UTF-8位置；不把隐藏Markdown标记计入用户光标。
- `replace_and_mark_text_in_range` 更新IME组合，未提交组合不触发保存；中文组合结束成为一个编辑事务。
- 鼠标命中由ShapedLine到字形位置，再转节点位置；选择按grapheme移动，不把Emoji/代理对截断。
- AccessKit使用稳定NodeId派生Element ID；编辑器暴露TextInput与TextRun合成子节点、选区和可访问动作。

## 6. 保存/外部修改/任务提交的精确算法

### 6.1 Ctrl+S

1. 在UI取当前revision和最小序列化结果快照；标记 `Saving(revision)`，不阻塞输入。
2. 后台按DocumentKey进入串行写队列，重新读取磁盘并核对BLAKE3指纹。
3. 与disk baseline不同：返回ExternalChanged；UI按用户政策直接采用外部内容并清掉未保存编辑，不写盘。
4. 相同：同目录create-new临时文件，写完整bytes并FlushFileBuffers，关闭临时写句柄；再核对当前源版本。
5. Windows ReplaceFileW替换已有目标；新建文件使用不覆盖未知目标的移动语义。失败保留原文件、清理临时文件并返回错误，不直接overwrite重试。
6. 重新获取文件身份和内容版本，发布CommitAck，包括请求revision、旧/新hash与写入内容。
7. UI若仍为请求revision则变clean；若保存中又有编辑，仅更新磁盘baseline并rebase后续事务，后续编辑仍dirty。

这不是与任意第三方进程的绝对CAS。保留双重校验、原子替换与提交后重读；记录无法消除的TOCTOU窗口，不对外宣称所有竞争都能无损解决。预先打开的第三方写句柄/原子替换行为纳入Windows故障测试。

### 6.2 watcher分辨自身提交

- watcher只报告“此路径可能变了”，不直接触发重载。
- 临时文件使用应用专用前缀，不进入索引，但不能屏蔽整个目录。
- 后台读取最新实际内容，与该文件已确认/进行中的提交hash和序号核对。
- 相同内容的重复/元数据事件只刷新身份；不是丢弃dirty的理由。
- 命中自身CommitAck更新索引，不重新用disk覆盖working。
- 不匹配的实际外部内容立即优先：新baseline与working、清dirty、清撤销；不要保留可恢复本地副本。
- 事件丢失时，在激活文件/保存前重读校验；不依赖watcher恰好一次。

### 6.3 Task组件提交，不保存无关正文

用户已选择：同字段冲突以组件操作为准。

设磁盘基线为B、当前可视化树为W，操作为 `SetField(task_node, field, value)`：

1. UI生成 `TaskIntent { doc_key, baseline_hash, task_anchor, field, value, request_id }`。
2. `task_anchor` 使用来源范围+结构身份及会话NodeId映射；同标题不等于同任务。Task若在磁盘不存在（仅在未保存正文新建）、已删除或身份不明，返回可定位错误，不提交整条草稿。
3. 验证磁盘仍为B；外部变化走统一外部优先，不将P硬套到新文件。
4. 对B只替换该字段的原始范围；缺字段则在该任务合适尾部插入；清除字段只移除对应字段片段，其他原始字节不变。
5. 得到B'，按6.1安全提交。失败不改working、不假勾选成功，组件恢复原显示并提示。
6. 成功后在最新W中定位同NodeId，把**目标字段**设为请求值，即使该字段有未保存修改；其他标题、字段、段落仍留在W。
7. baseline置为B'；清除/重写history中涉及该Task该字段的旧逆操作，以B'为基线重放其余语义事务。撤销其他文本不能恢复旧priority或抵消磁盘已提交字段。
8. 结构历史里若含Task快照，恢复时应用已提交字段overlay；已删Task或无法映射则停止组件操作并诊断，不猜测重建。
9. 其他编辑导致W与B'不同则仍dirty。后续Ctrl+S提交剩余变化，不再次写回旧字段。

必须通过的例子：磁盘 `priority=3`；W中改为2并修改上方段落；组件设为9。结果：磁盘只有3→9；W优先级9且段落仍dirty；撤销段落不把9变回2/3。

## 7. SQLite Schema 与中文搜索

### 7.1 单库，只保存派生内容

`migrations/001_index.sql` 初始结构：

```sql
PRAGMA foreign_keys = ON;
CREATE TABLE files (
  id INTEGER PRIMARY KEY,
  resolved_path TEXT NOT NULL UNIQUE,
  volume_key TEXT,
  os_file_id BLOB,
  content_hash BLOB NOT NULL,
  byte_len INTEGER NOT NULL,
  mtime_ticks INTEGER NOT NULL,
  parse_version INTEGER NOT NULL,
  generation INTEGER NOT NULL
);
CREATE TABLE aliases (
  logical_path TEXT PRIMARY KEY,
  file_id INTEGER NOT NULL REFERENCES files(id) ON DELETE CASCADE,
  area TEXT NOT NULL CHECK(area IN ('atlas','efforts','archive','other')),
  excluded INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX aliases_file ON aliases(file_id);
CREATE TABLE tasks (
  file_id INTEGER NOT NULL REFERENCES files(id) ON DELETE CASCADE,
  ordinal INTEGER NOT NULL,
  source_start INTEGER NOT NULL,
  source_end INTEGER NOT NULL,
  anchor_hash BLOB NOT NULL,
  title TEXT NOT NULL,
  completed INTEGER NOT NULL CHECK(completed IN (0,1)),
  start_date TEXT,
  due_date TEXT,
  priority INTEGER CHECK(priority BETWEEN 1 AND 9),
  diagnostics_json TEXT NOT NULL DEFAULT '[]',
  PRIMARY KEY(file_id, ordinal)
);
CREATE VIRTUAL TABLE search_long USING fts5(
  path_fold, title_fold, body_fold, tokenize='trigram'
);
CREATE VIRTUAL TABLE search_short USING fts5(
  grams, tokenize='ascii'
);
PRAGMA user_version = 1;
```

两个FTS表的rowid均等于files.id；应用必须在同一SQLite事务内显式删除/插入对应FTS与Task记录，外键不会自动清理虚表。普通FTS而非contentless，初版优先正确可维护；以后优化磁盘占用不改变查询契约。

`files.id` 是索引内部ID，不写Task UID。原子替换后保持同resolved_path文件记录、更新OS身份；链接别名通过aliases映射。同一目标多个路径只显示一条结果，默认优先非Archive可见别名。Archive判定按逻辑根路径分区，不是权限：Efforts里指向同文件的显式链接可形成活动别名。

### 7.2 索引管线

`scan → stat/read/hash → parse snapshot → text/task projection → transaction`。

- 开始先加载持久UI，不等待全库扫描。
- 单次扫描发现集合标记scan_generation，扫描完成后清除已消失alias；失败扫描不能清空全库。
- 单文件写后按内容hash跳过重复解析；提交前检查generation，旧结果不能覆盖新内容。
- 初始DB设置WAL、busy_timeout 2000ms、cache_size约32MiB；查询与写事务短时分批。
- 所有文件读完即释放，不把200MB语料整体常驻内存。
- 未保存working不进全局索引；列表代表磁盘事实，打开文档可单独显示未保存标记。

### 7.3 不回避中文短查询

文本正规化固定为NFKC + Unicode lowercase，不做语言分词；文件名/标题/正文采用同一变换。正文来自Markdown文本投影，Task字段另保留为可搜索文本。

- 查询长度≥3个Unicode标量：`search_long MATCH`，把用户输入按字面短语安全引用，不暴露SQL/FTS操作符；参数化SQL。
- 长度1：查询token `u<codepoint_hex>`。
- 长度2：查询token `b<cp1_hex>_<cp2_hex>`。
- `search_short.grams` 为该文件正规化文本的去重unigram/bigram token集合，以ASCII空格分隔，所以中文短词不依赖trigram扫描200MB正文。
- FTS返回候选后，用正规化字段contains复核精确匹配，过滤Archive/ignore别名。
- 首批50条，文件名/标题命中优先，正文其次，再以路径稳定排序；后续分页，不为了精确总数阻塞首批。
- 查询每次发新generation；旧查询取消；输入debounce初值20ms，计入100ms预算。
- 长短查询的上下文片段从匹配文档按需生成，正规化位置不能直接用作原文字节下标，需保留映射或二次匹配。

测试必须包括“中”“中文”“项目方案”、ASCII、全角、Emoji、引号/百分号、重复别名和Archive过滤，验证结果而非仅看耗时。

## 8. 文件发现、规则与普通链接

- 调用GitignoreBuilder(root)，只add根目录 `.ohmyworkignore` 和内置规则；不调用build_global，不读取`.git/info/exclude`等。
- 使用自己的目录遍历器，匹配logical路径；对目录目标取Windows卷+FileId维护当前递归栈防环，再用全局目标缓存减少重复扫描。
- 白名单规则与父目录排除按gitignore风格语义处理；提供“显示排除项”仅用于文件树查看，不偷偷纳入全文搜索。
- 文件树虚拟化，目录展开才生成子节点；扫描和UI树分离。
- `[x](../a.md)` 从当前文件父目录解析；`[x](/Atlas/a.md)` 从唯一root解析；HTTP/HTTPS外部浏览器。
- 不生成heading slug，不建立引用图，不在移动/重命名文件时重写其他文件。
- 文件操作仅提供基础新建目录/笔记、重命名/移动、系统中显示；删除通过系统回收站/确认流程单独实现，不夹带永久删除默认。

## 9. Pi 适配：具体到进程和消息

### 9.1 启动配置

```rust
struct PiLaunch {
    executable: PathBuf,
    args: Vec<OsString>,
    cwd: PathBuf,
    session: NewOrResume,
}
enum NewOrResume { New, Resume { session_path: PathBuf } }
```

PATH中解析用户Pi，必要时用户指定。恢复首版采用用户通过文件选择器选择已有Pi Session文件，不扫描用户私有认证/配置以猜历史位置；提供选择文件入口和最近明确选择路径，不强制唯一Session。

启动只增加官方RPC模式与用户明确选择的session参数，不注入工具白名单、system prompt、no-extensions或approve开关。不运行探测prompt；在用户明确启动后，用官方只读state命令核验连接。

Windows `.cmd` 由单独Launcher处理标准shim，不把用户prompt拼入shell；prompt只经stdin JSON发送。显式自定义命令拆分为程序与参数数组，不用不可靠空格split。启动失败报告路径/原因但日志脱敏。

### 9.2 JSONL与状态机

- ByteFramer累积字节直到LF，去可选CR，再UTF-8解码/serde解析；Unicode U+2028/U+2029不能拆帧。
- request_id→oneshot映射只关联response，事件独立分派；stderr单独异步读。
- 状态：Stopped → Starting → Idle/Running → Closing → Stopped/Failed。
- 消息按contentIndex累积text/thinking/tool block，message_end替换完整最终值。
- prompt success disposition=handled不等待不存在的run；agent_end不等于idle，agent_settled才表示当前自动工作结束。
- 未知普通event保留类型诊断并忽略；未知交互request必须有取消/错误路径，不允许永久等待。

### 9.3 不设计宿主Agent策略

用户点击发送时只发送用户消息和显式附件，不自行决定steer/follow_up。如果当前Pi拒绝缺少streamingBehavior的请求，保留草稿并显示官方错误；不自动重试或替用户改成queue。这是尊重协议结果，不是宿主新建Agent排队系统。

context payload采用可见文本包装：每个文件显示原始标签与绝对路径，不读取内容；选区附来源标签与当次文本快照。所有附加清单用户可删，发送前可查看最终内容。不同cwd不会把相对路径解释到错误项目。

### 9.4 UI与关闭

侧栏承载select/confirm/input/editor原生请求控件，按id答复；关闭时取消未完成UI请求。

本计划采用“收起/关闭为同一退出入口”，符合此前关闭面板停止运行的选择，不提供隐藏后台运行按钮；切换正文标签不关闭侧栏。若要独立隐藏并继续运行，必须未来显式变更，不在本次偷偷加入。

关闭顺序：发abort（运行中）→等待最多2秒响应→关闭stdin→最多3秒等待退出；超时仍显示“未退出”，提供用户显式强制终止该Pi子进程。不得假定abort撤销了外部工具副作用，也不得自动杀用户所有同名进程。

## 10. Pane、Homepage、主题与预览怎么实现

### 10.1 GPUI Kit Dock、Pane与状态

用 `gpui_kit::component::dock::{DockArea, DockLayout, DockAreaState, Panel}` 提供标签、拖放、嵌套横/纵分割、最小尺寸和布局dump/load，不再自建一套并行 `PaneNode` 交互引擎。应用持有的持久边界仍是版本化纯数据：

```rust
struct PersistedDockState {
    schema_version: u32,
    kit_layout_version: u32,
    dock: DockAreaState,
}
enum TabRef { Markdown { path: PortablePath }, Preview { path: PortablePath }, Home }
struct CanvasState { version: u32, pan: [f64;2], zoom: f32, widgets: Vec<WidgetState> }
struct WidgetState { id: Uuid, kind: BuiltinWidgetKind, rect: WorldRect, z: u32, options: Value }
```

每种可恢复标签实现/适配Kit `Panel`，注册固定panel name和恢复factory；panel序列化payload只保存 `TabRef` 与视图状态。Markdown Panel通过DocumentKey取得共享文档实体，绝不持久化Entity指针、正文或Undo历史。缺失文件由factory生成placeholder。Kit状态外再包应用schema/version以执行校验和迁移；重启不启动Pi、不恢复脏正文。

画布：`screen = viewport_origin + pan + world * zoom`，反变换统一放transform.rs。鼠标下缩放调整pan保持所指world点不动；zoom初值范围0.25–2.0。组件z-order倒序hit-test，拖动用world delta，键盘每次10逻辑单位/精细1单位；只渲染可见矩形及边缘缓冲。

组件最小尺寸由kind定义，暂用160×100逻辑单位起；无限画布不是无限创建内存对象。初版线性可见性过滤足够，100组件夹具通过再考虑空间树，不提前建框架。

默认组件：分区入口、最近/置顶页面、Task、Pi状态/入口、快捷动作；无日历。初始布局可以全部删除。JSON导入解析到临时结构，验证版本、kind、数量、有限坐标与尺寸，成功后整体替换并提供撤销该次布局导入。

### 10.2 主题与快捷键

- 手动导入复制到themes/<uuid>/source.json，metadata保存family信息和内容hash；重新导入同一条目保持import UUID。
- 映射结果先生成ohMyWork语义主题快照，再适配到GPUI Kit `Theme`/tokens并通过 `Theme::update` 原子应用；自定义编辑器、Raw、Canvas和Pi专有token保留在应用扩展快照。禁止使用Kit `ThemeRegistry::watch_dir`自动扫描或监听Zed来源。
- 映射表明确 `background→window/Kit background`、`text→text.primary/Kit foreground`、`panel.background→panel`、`editor.background→editor` 等；每个Token在表中有内置light/dark兜底。
- 检查alpha与真实背景合成后的sRGB相对亮度。正文/选中文本4.5:1，焦点和必要非文本状态按3:1；disabled使用产品可辨识目标而非谎称正文AA硬要求。
- 背景不动，foreground分别向黑/白混合，用二分搜索找到达到阈值的最小改变，选改动更小者；必要时为focus加独立边线。记录original/resolved/reason，不改原JSON。
- keymap.jsonc解析为受限 `[{context, bindings}]`，context为明确枚举而非可执行表达式；冲突以用户项覆盖默认、同context后项覆盖前项并诊断。
- watcher重载先校验整份，失败保留last-known-good；命令面板显示已解析实际键位。保留安全恢复入口，不能导入配置后无法恢复。
- 所有用户文案用稳定StringId查zh-CN/en字典，测试两份key集合相同；目录名/存储键/Pi输出不翻译。

### 10.3 图片/PDF预览

`omw-preview-worker.exe` 按需启动，一个工作线程依次解码/渲染；Pdfium实例只存在该进程，不通过共享内存传Rust对象。

控制管道使用 `u32_le header_len + JSON header + payload`，header包含request_id/kind/payload_len/version；位图用二进制RGBA而不是Base64 JSON。验证宽高乘法溢出、stride和payload上限。

请求：Open(path)、PageInfo、Render(page,target_size,generation)、Close(document)。回复：metadata、bitmap、typed error。过期generation位图丢弃；关闭文档取消待排队render。无法中断的native调用超时由worker监督器结束进程并重建，不让主UI挂住。

- 从应用安装目录的绝对路径加载固定pdfium.dll，禁止系统/cwd搜索回退。
- 只用非V8构建，不执行PDF脚本、外链或文件动作；只渲染。
- 可见页+前后各一页预取，缩放时先显示旧位图、后台替换；缓存上限96MiB起，按字节LRU。
- 图片预检尺寸/解码限额；初版单bitmap最大64MiB，超过则按缩略/分块渲染能力处理或明确诊断，不能申请溢出大小。
- UI与worker总资源分别报告，不能把内存挪到子进程就声称省内存。
- 预览进程不是OS沙箱；后续是否加受限令牌需独立评审，不假装进程隔离等于安全隔离。

## 11. 分成28个可验证步骤执行

每步是可单独审阅的改动单元，不要求自动git commit。按顺序完成；完成定义包含列出的测试和演示，不是“文件已创建”。

### 01 — 固定开发环境，写doctor

**文件**：rust-toolchain.toml、tools/doctor.ps1、docs/development.md。

**顺序**：检查已有安装 → 用已有VS开发shell获得cl/link → 核验SDK和CMake → 经授权安装缺失Rust1.98.1 → 仅补GPUI Kit Windows构建所需依赖 → 输出工具版本/来源。不照抄构建整个Zed需要的PostgreSQL/wasmtime设置。

**验收**：doctor能区分“未安装”与“未载入环境”；不修改全局PATH/Pi；Windows MSVC空程序可编译。

### 02 — 创建最小Cargo工程与GPUI Kit窗口

**文件**：workspace manifest、omw-app/main.rs、Cargo.lock、CI。

**顺序**：精确固定 `gpui-kit = =0.7.0` → 注册默认Assets → `application/init/open_window` → 用长期Entity持有Kit `InputState`并渲染Input/Button → AccessKit名称/焦点 → `test-support` UI测试 → Windows CI fmt/clippy/test/build。不得直接覆盖Kit固定的GPUI快照。

**测试**：`cargo run -p omw-app`；中文IME组合、Emoji、按钮/输入焦点与屏幕阅读基本动作；`#[gpui_kit::test]`通过真实组件交互验证状态。失败修固定依赖，不偷偷换WebView或裸GPUI依赖。

### 03 — 建领域类型和lossless解析

**文件**：omw-document/model.rs、parse.rs、source_map.rs、fixtures/markdown。

**顺序**：SourceSlice/ByteOffset/NodeId → 行字节表 → Comrak owned AST转换 → 源间隙 → Raw → Task符号范围。

**测试**：`cargo test -p omw-document --test roundtrip`：无操作字节完全一致，UTF-8/BOM/CRLF、嵌套/表格/Raw。

### 04 — 实现最小文本与格式编辑事务

**文件**：edit.rs、history.rs、serialize.rs。

**顺序**：文本插删与grapheme → bold/italic → split/join段落 → Undo/Redo → 最小Patch planner → 输出重解析校验。

**测试**：只改一个词不改邻段；转义/HTML实体/反引号/多字节选区；1000次随机编辑的树/源码一致性属性测试。

### 05 — GPUI Kit应用接入自定义段落编辑器

**文件**：editor/view.rs、element.rs、input.rs、selection.rs、a11y.rs。

**顺序**：共享DocumentSession → Kit滚动/工具栏外壳 → 自定义可见块layout → 通过Kit重导出GPUI做shaping/hit-test → UTF16Selection/marked text → key actions → 合成TextRun可访问节点。不能用Kit源码Editor代替无损Markdown编辑模型。

**测试**：同文件双视图内容一致；跨行选择/复制；中文组合为一次Undo；无隐藏语法光标跳跃。

### 06 — 唯一Workspace与LocalAppData

**文件**：omw-local/paths.rs、workspace.rs、state.rs；ui初始设置。

**顺序**：目录选择/预览 → 创建缺失Atlas/Efforts/Archive及id → 原子settings保存 → 重启加载。便携模式先预留纯数据接口，实际迁移在步骤23。

**测试**：已有内容不搬迁、同名文件不覆盖、只读报错、ID不重置，不创建项目对象。

### 07 — 安全Ctrl+S与关闭行为

**文件**：atomic_write.rs、write_queue.rs、editor保存命令。

**顺序**：磁盘baseline/hash → 按文件串行请求 → temp+flush+replace → CommitAck → 保存中新增编辑rebase → 保存/放弃/取消。

**测试**：`cargo test -p omw-local --test files`；磁盘满/锁定/写失败注入，旧文件完整；保存时继续输入仍dirty；无草稿持久化。

### 08 — 外部版本优先与自身事件去重

**文件**：watch.rs、identity.rs、DocumentSession reducer。

**顺序**：notify队列 → 路径合并 → 重读hash →匹配self commit →外部Reload清history。补激活/保存前重新验证。

**测试**：外部改写脏文件立即替换且Undo不能恢复；自写回声不丢dirty；事件交错/丢失/临时替换/外部删除。

### 09 — 完成GFM可视化编辑

**文件**：editor/toolbar.rs、各Node渲染、结构edit/serialize。

## 13. 明确的技术风险与停止条件

1. **可视化编辑保真**：不是安装Comrak就完成。步骤03–09是首要工作量；若源映射/IME/Raw有不可修复损失，停止扩展UI并修该层，不回退源码模式。
2. **Task重基**：组件胜出的仅是目标字段，不能用整文件overwrite模拟。步骤14夹具不通过，不能接入Homepage快捷Task。
3. **第三方写盘竞争**：ReplaceFileW提供替换，不提供对任意进程的CAS。行为边界与测试如实记录，不能保证操作系统未提供的原子条件提交。
4. **GPUI Kit/配套GPUI API变动**：精确锁定Kit 0.7.0及Cargo.lock，不直接覆盖其 `gpui-pre-*` 快照；升级Kit需重跑组件、Dock持久化、输入/IME、主题、无障碍和Windows平台测试，不能仅cargo check。
5. **PDF native风险**：固定非V8二进制、绝对DLL路径、独立进程与限额；资产校验和/许可证不完整不得打包发布。
6. **内存/搜索**：短词索引增加磁盘体积，保存足够但只按需读。若预算失败，用基准定位，不删除短中文搜索或隐瞒worker占用。

本文已经给出实现路线，不把选库和核心算法留给执行者自由发挥。仍需真实构建验证的部分是工程风险，不是假装已经通过的结论；计划批准即采纳其中具体默认值，若需调整在实施前明确修订。
