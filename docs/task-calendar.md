# 基础 Task 与日历延期

> 此文件保留原路径以维持引用。旧版 V1 iCalendar 规格已被 [ADR-0009](adr/adr-0009-basic-tasks-calendar-v3.md) 替代。

## 1. V1 数据模型

Task 是普通 Markdown checkbox，标题是工作内容，checkbox 是唯一完成状态。

```md
- [ ] 撰写方案 [start:: 2026-10-01] [due:: 2026-10-15] [priority:: 9]
- [x] 整理资料 [priority:: 3]
- [ ] 没有额外字段的任务
```

| 字段 | 当前约定 |
|---|---|
| checkbox | `[ ]` 未完成、`[x]` 完成；不增加独立 status |
| start | 可选日期，`YYYY-MM-DD` |
| due | 可选日期，`YYYY-MM-DD` |
| priority | 可选整数 1–9，**9 最高、1 最低** |

字段采用 Dataview 内联外形，不用 Emoji。没有字段就保持未设置，不补写默认状态或优先级。CommonMark/GFM 之外仅解释上述基础任务字段，保留其他原文；不执行 Dataview 查询。

不要求 V1 Task 具备 UID、独立 JSON 文件或数据库身份。索引用源文件/范围等定位；复杂稳定身份方案不得为了未来 ICS 提前强加。

## 2. 功能边界

任务组件提供汇总、定位、勾选及基础字段修改。遵循 `.ohmyworkignore`；Archive 默认不参与，用户可显式纳入。Atlas/Efforts 是目录分类，不是 Task 状态。

V1 不包含：Calendar、ICS 导入导出、RRULE、重复实例、任务依赖、时区、时间精度、提醒或独立 status。

## 3. 写回契约

- 正文编辑只有 Ctrl+S/保存命令才落盘。
- Task 组件操作立即提交对应任务，使用文档服务的安全替换流程。
- 若同文件有未保存正文，磁盘只更新 Task，内存同步 Task，其他正文继续 dirty。
- 不保存全文、不要求用户先提交全部正文、不把自写事件当外部覆盖。
- 对真正外部变更则执行应用统一政策：外部版本优先、未保存编辑彻底丢弃。
- 源任务被删除、定位失效或同任务同时被编辑时，不能盲目按旧行号写回；冲突 UX 尚待定。

## 4. 验证

- 普通/嵌套 checkbox、多个任务和重复标题的正确定位。
- 日期与优先级合法性，缺失和未知字段无损保留。
- 9 高于 1；不沿用旧 iCalendar 的反向优先级。
- Task 修改只更新目标范围，不顺带保存脏正文。
- 自写通知不会误触发未保存内容丢弃；真实外部修改会按已确认策略替换。
- Archive/ignore 排除与用户主动纳入。
- 从 Markdown 重建索引，不产生第二份权威 Task。

无效值、重复字段、字段展示、任务排序和同任务冲突操作仍须设计，不在本文擅自选定。

## 5. V2 / V3

V2 Dataview 功能级兼容独立于 V1 Task 格式：DQL、内联查询和主要 `dv` API；不承诺 Obsidian app、DOM 或其他插件运行时。

日历与 ICS 统一放 V3。之前 RFC 5545/9253、UTC 归一化、直接 iCalendar 属性名的 V1 承诺已经撤销，未来如采用这些标准，需明确映射并重新决策。

尤其不能直接把当前 priority 导出为同值 iCalendar PRIORITY：方向相反。start/due 的日期型含义、完成映射、UID、重复/依赖、时区及未知属性保留都留到对应版本，不阻塞基础工作台。
