# Product Requirements

> 参考规格：已确认决策。实现状态以实际代码与人工验收记录为准；未验证的行为不视为已验证。

## 1. 定位与版本

个人、本地优先、无账号/必需云服务的 Rust/GPUI 工作站。适配已有工具与人员，不建设团队协作平台。

| 版本 | 范围 |
|---|---|
| V1 | Windows 11 x64；单一 Workspace；原生 GPUI 同区 Markdown 渲染编辑；基础 Task；搜索；无限画布 Homepage；图片/PDF 只读预览；Pi 界面；主题、双语、快捷键、当前用户安装包 |
| V2 | 独立进程插件与连接器、资源信封、自动化、Dataview 功能级兼容 |
| V3 | 日历与 ICS；复杂重复、依赖、时区等重新设计 |

| V1 不做 Live Preview、可视化双模式、独立全局源码模式、多 Workspace 注册系统、独立项目对象、反向链接、引用自动改写、DQL/DataviewJS、日历、ICS、RRULE、依赖和提醒。

## 2. 内容组织与存储

- **WS-001**：仅一个 Workspace，根目录为 Atlas/、Efforts/、Archive/ 三个真实文件夹。
- **WS-002**：Atlas 放脱离时间、多项目共用的知识；Efforts 放正在投入的项目和领域；Archive 放不再使用、待整理或休眠内容。
- **WS-003**：项目和领域是普通文件夹，不要求项目 ID、属性或模板。既有目录原地使用，不复制整个目录。
- **WS-004**：应用自动创建最小 `.ohmywork/id` 作为 Workspace 稳定身份。这替代此前“默认不创建 .ohmywork/”的决定。
- **WS-005**：设置、布局、主题、索引、日志默认全部在 `%LOCALAPPDATA%\ohMyWork\`。便携模式开启后才在 Workspace 保存额外可迁移状态。
- **WS-006**：使用一个全局 SQLite 索引，Markdown 内容可重建其派生记录；用户布局和设置不因此变成可随意删除的数据。

无需继续设计多 Workspace 复制、注册、切换和跨 Workspace 汇总。V1 已实现首次选择根目录、缺失顶层目录初始化、`.ohmywork/id` 创建及 LocalAppData 设置保存；便携模式细节仍待后续里程碑。

## 3. 文件树、搜索与普通链接

- **FS-001**：文件树显示所有未被专有规则排除的文件；内置编辑仅面向 Markdown。
- **FS-002**：根目录 `.ohmyworkignore` 使用 gitignore 风格匹配语法，但完全不读取 `.gitignore`。文件不存在时采用应用默认排除项；规则文件只在用户主动创建时写入。
- **FS-003**：按系统语义跟随符号链接和 Windows Junction，包含根目录外目标，检测循环。仅影响 ohMyWork，不限制 Pi。
- **SEARCH-001**：搜索文件名/路径、标题和 Markdown 正文，显示片段；任务字段可作为文本命中。不索引图片/PDF 正文，不做 OCR。
- **SEARCH-002**：Archive 默认不参与搜索或任务汇总，用户可显式纳入。原先“当前/全部 Workspace”的选择随单 Workspace 决策失效。
- **LINK-001**：只做普通可点击链接。本地文件由应用或系统按类型打开；HTTP/HTTPS 交给默认浏览器。
- **LINK-002**：相对路径相对当前文件解析；`/path` 表示 Workspace 根目录内路径。
- **LINK-003**：不做反向链接、标题 slug 规则或重命名/移动后的链接联动。原先“Workspace 内自动更新链接”决定已被替代。

## 4. 编辑与保存

### 4.1 Markdown 源码编辑

- **EDIT-001**：CommonMark + GFM 为任务语义识别基线，不支持 Obsidian Wiki Link、嵌入、Callout、Block ID 或 Properties 等专属扩展。
- **EDIT-002**：默认和唯一编辑模式为原生 GPUI 同区 Markdown 渲染编辑（见 ADR-0012）；平时隐藏已识别的 Markdown 标记，活动段落/行内构造/表格单元格在原位置显露必要原文标记以编辑；同时呈现格式化标题（按层级放大）、粗体/斜体/删除线、GFM 表格网格等语义样式，不退化成无格式纯文本；不提供块级所见即所得、双模式、Live Preview 或全局源码模式切换。
- **EDIT-003**：Raw、HTML、损坏或未知扩展均作为普通源码可编辑；不得自动执行原始 HTML。
- **EDIT-004**：直接保存用户编辑后的源字节；不经富文本序列化，不格式化或规范化未改动内容。
- **EDIT-005**：基础 Task 字段是 CommonMark/GFM 之外的有限专项解释，不因此承诺完整 Dataview 或 Obsidian 方言。

### 4.2 正文显式保存与外部优先

- **SAVE-001**：仅 Ctrl+S/保存命令写入正文；无自动保存。
- **SAVE-002**：关闭含未保存修改的标签或应用时提供保存/放弃/取消，可批量处理。
- **SAVE-003**：不持久化未提交编辑，不保存恢复草稿。应用崩溃或断电会丢失未保存内容。
- **SAVE-004**：检测到真实外部修改，立即采用磁盘版本，无论缓冲区是否有本地修改；本地未保存编辑彻底丢弃，不保留撤销恢复，不要求覆盖前确认。
- **SAVE-005**：产品文档与界面应明确上述丢失风险；不得把历史“脏时合并/恢复快照”写成现行行为。
- **SAVE-006**：Ctrl+S 使用同目录临时文件、完整写入后 Windows 原子替换。提交前校验源版本，已知外部变化优先；失败保留原文件并报告，不能降级为无提示原地覆盖。

### 4.3 Task 组件立即保存例外

- **SAVE-007**：Task 组件勾选或改字段立即写回该任务，不等待 Ctrl+S。
- **SAVE-008**：同文件存在脏正文时，只保存任务变化，其他正文保持未保存；内存文档同步这次任务提交，不顺带保存全文。
- **SAVE-009**：这是宿主内部已知修改，不适用“外部修改彻底丢弃”。必须区分自身文件事件与真正外部变化。
- **SAVE-010**：Task 局部提交必须验证磁盘版本、固定源范围及旧字节。目标源范围或保留历史状态无法与磁盘基线逐字节验证时，拒绝提交；不自动搜索重定位、不写错任务、不顺带保存脏正文。

## 5. 基础 Task

- **TASK-001**：事实来源是 Markdown `- [ ]`/`- [x]` 和标题；checkbox 是唯一完成状态，没有独立 `status` 字段。
- **TASK-002**：可选 `[start:: YYYY-MM-DD]`、`[due:: YYYY-MM-DD]`、`[priority:: 1..9]`。
- **TASK-003**：9 最高、1 最低；这不是 iCalendar PRIORITY 的方向。缺失字段保持未设置，不写默认值。
- **TASK-004**：只有日期，无时间、时区、提醒、重复或依赖。
- **TASK-005**：汇总、定位和修改这些基础数据，遵循 Archive 和 ignore 规则；其他字段保留但不赋予行为。

详见 [Task 规格](task-calendar.md)。

## 6. 主窗口与 Homepage

- **UI-001**：一个主窗口，标签属于 Pane；支持可嵌套横向/纵向分栏、调整大小、移动标签及键盘操作。
- **UI-002**：重启恢复 Homepage、Pane 树、标签、选中项、滚动位置与内容根目录；不恢复未保存编辑。缺失文件用可关闭诊断占位。
- **HOME-001**：Homepage 为无限画布，组件使用逻辑坐标自由摆放，可平移、缩放、定位组件和适合全部内容，不自动改成响应式网格。
- **HOME-002**：图形界面维护布局，内部持久化为事实来源；版本化 JSON 仅用于导入、导出和迁移，不做实时配置文件。
- **HOME-003**：提供可删除的起始布局。内置组件范围为内容入口、最近/置顶页面、基础任务、Pi 会话/状态与快捷动作；删除原日历组件及多 Workspace 列表。
- **HOME-004**：V1 没有插件组件系统。具体起始布局和画布尺寸约束待定。
- **PREVIEW-001**：内置图片与 PDF 只读预览，无编辑、批注或 OCR；其他非 Markdown 文件交给 Windows 默认应用。

## 7. Pi 界面适配

- **PI-001**：仅使用用户安装的官方 Pi RPC，PATH 发现并允许显式路径/命令；V1 不自动扫描或修改 WSL。
- **PI-002**：用户自行指定 cwd（不限制在 Workspace 内），并在切换时选择新建或恢复会话；撤销唯一 Workspace 会话和自动恢复固定绑定。
- **PI-003**：不修改用户模型、认证、工具、Skills、Extensions、Prompts、队列等配置，不自行制定 Agent 排队/插话策略。
- **PI-004**：提供可收起、可调宽度的原生侧边面板；显式关闭面板时 abort 当前处理并有序关闭进程，不承诺暂停续跑。仅视觉收起/切换标签是否视作关闭仍需明确。
- **PI-005**：用户输入文本，显式附加清单可检查/移除；确认发送后，文件传路径、选区传文本。
- **PI-006**：不自动发送 Atlas/Efforts/Archive、任务或搜索结果。Archive 内容可由用户主动附加。Pi 自主读取与加载指令仍由用户配置决定。
- **PI-007**：select/confirm/input/editor Extension UI 请求映射为 GPUI 原生对话层，正确处理响应与取消。
- **PI-008**：协议持续读流、关联响应、区分接受与完成；生命周期事件仅用于呈现，不当作工具审批。

详见 [Pi 集成](pi-integration.md)。

## 8. 个性化、分发与隐私

- **THEME-001**：手动导入 Zed Theme Family，原始 JSON 复制到 LocalAppData；不扫描 Zed 目录，不监听来源，重新导入才更新。
- **THEME-002**：映射到内部语义 Token；未知字段忽略、缺失字段确定性回退。关键对比度不合格时自动安全覆盖，并展示修正清单，不改变来源文件。
- **KEY-001**：默认键位 + `%LOCALAPPDATA%\ohMyWork\keymap.jsonc`，命令面板显示实际绑定；不做图形化键位编辑器，不修改 Pi keymap。
- **LANG-001**：简体中文和英文可切换，目录名不翻译，Pi 内容不自动翻译。
- **DIST-001**：Windows 11 x64 当前用户安装包，无需管理员权限，提供快捷方式、卸载入口；手动升级，无自动更新。
- **LOG-001**：仅本地日志和用户主动导出的诊断包，无遥测或自动上报；默认排除正文、Pi 对话及凭据。
- **A11Y-001**：WCAG 2.2 AA、键盘优先、可见焦点、非颜色提示、缩放、减少动态效果；需实测验证。

## 9. 性能预算（批准目标，尚未实测）

### 数据集

一万篇 Markdown、约 200 MB、两万条任务。附件体积、Pi 子进程和 GPU 显存另行统计，不混入主程序私有内存数字。

### 基准机（本次本机只读检测）

| 项目 | 配置 |
|---|---|
| OS | Windows 11 家庭版中文版 x64，Build 26200 |
| CPU | Intel Core Ultra 7 255HX，20 核/20 线程 |
| 内存 | 约 32 GB，系统报告 31.4 GiB |
| GPU | Intel Graphics + NVIDIA RTX 5070 Ti Laptop GPU |
| 磁盘 | NVMe SSD，两块约 1 TB |
| 当前显示模式 | 2560 × 1600，60 Hz |

实际渲染 GPU、数据集所在盘、驱动、供电模式和 DPI 缩放必须随测试报告记录；显卡清单不证明应用实际使用独显。

### Release 构建预算

| 指标 | 目标 |
|---|---|
| 进程启动到真正可交互 | P95 ≤ 2 秒 |
| 索引就绪后搜索首批结果 | P95 ≤ 100 ms |
| 普通页面输入到显示 | P95 ≤ 50 ms |
| 稳态应用私有内存 | ≤ 500 MiB |

首次索引单独测量且不得阻塞界面；不以“窗口出现”冒充可交互。冷/热启动、普通页面大小、采样次数、搜索起算点和预览压力场景仍需固定成可复现方法。目标不是已达成的宣传数字。

## 10. 验收与开放项

发布前验证全部上述契约，尤其是外部覆盖的丢失行为、任务范围提交与脏正文共存、Raw 原样保留、无日历范围、Pi 非干涉、键盘/双语和性能预算。

尚待决定：

- Task 元数据呈现、缺失/无效值、排序和筛选细节。
- 画布重叠、焦点、缩放/尺寸约束、具体内置布局。
- Pi 兼容矩阵、候选历史发现、视觉收起与进程关闭边界、无副作用探测方式。
- keymap 冲突、配置错误和重载。
- 安装器/签名、手动升级迁移、日志脱敏/轮转、测试方法与 CI。

已锁定：

- 图片 png/jpeg/webp/gif 首帧；PDF 独立进程 `pdfium-render 0.9.4` + PDFium `chromium/7881` 非 V8；许可证与资源上限见 plan 21。
- 主题安全覆盖：WCAG 2.2 相对亮度 sRGB；正文/选中 4.5:1，焦点 3:1，错误 4.5:1；禁用 3:1 相对背景与相邻；二分混合修正，源 JSON 不改。


这些是后续规划议题，不授权实现者悄悄补回已删除功能。
