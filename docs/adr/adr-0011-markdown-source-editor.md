# ADR-0011: 整篇 Markdown 源码编辑与严格哈希写入保护

## Status

**Accepted**。部分替代 ADR-0008 的编辑模式决定；DEC-004 至 DEC-007 的保存边界继续有效。

## Context

用户选择将逐块可视化编辑替换为单一整篇 Markdown 源码编辑器。源码标记、Raw、HTML 和未知语法均可编辑；内容仍是 Markdown 文件，不执行 HTML。编辑输入不要求解析成功，也不规范化未改动文本。正文显式保存、外部修改优先及 Task 局部提交继续有效。

Task 局部写盘必须能证明目标源范围仍对应磁盘基线，并且不能把未保存正文写入磁盘。任一基线、源范围或旧内容无法验证时，失败关闭并拒绝写入。

## Decision

- **DEC-001**：V1 使用唯一的整篇 Markdown 源码编辑模式；不提供块级所见即所得、双模式或 Live Preview。
- **DEC-002**：整篇源文本直接作为编辑缓冲与保存内容。输入不依赖 Markdown 解析成功，不对全文或未编辑内容做格式化、换行规范化或序列化。
- **DEC-003**：Raw、HTML、未知语法及未闭合围栏均作为普通源码可编辑；应用不执行 HTML。
- **DEC-004**：ADR-0008 的显式正文保存、关闭脏内容三分支、外部修改丢弃本地编辑、自写事件识别、Task 局部提交及原子安全写盘继续有效。
- **DEC-005**：Task 提交必须验证磁盘版本、固定源范围和旧字节；所有保留的源码历史状态在目标范围之前及范围内必须与基线一致。任一验证失败则不写盘、不自动定位、不保存脏正文。
- **DEC-006**：Task 提交只更新目标字段，并将该补丁应用到保留历史状态，确保 Undo/Redo 不会恢复已提交字段旧值；目标之后的脏正文继续留在内存。

## Consequences

### Positive

- **POS-001**：源码标记始终可见，任何 Markdown 文本都可直接编辑。
- **POS-002**：保存的 UTF-8 源字节由用户编辑内容决定，不经过富文本重序列化。
- **POS-003**：Task 写盘失败关闭，不依赖猜测行号或扫描相似文本定位。

### Negative

- **NEG-001**：源码编辑暴露 Markdown 标记；不提供富文本预览或可视化双模式。
- **NEG-002**：严格范围校验会拒绝目标前方或目标内部存在未保存改动及相关历史差异的 Task 操作。
- **NEG-003**：整篇输入、文档级历史、IME、多个编辑表面和 Task 历史重基需要共同维护一致性。

## Alternatives Considered

### 继续使用逐块可视化编辑

- **ALT-001**：通过语义节点和局部序列化修改 Markdown。
- **ALT-002**：用户选择直接编辑整篇源码；继续块编辑无法满足该编辑方式。

### 自动搜索并重定位 Task

- **ALT-003**：在当前正文中寻找相同 hash、标题或字段以推断目标位置。
- **ALT-004**：相同内容不构成任务身份；猜测可能写错任务，因此采用固定基线范围并拒绝无法验证的操作。

### Task 操作保存整个脏文档

- **ALT-005**：将 Task 修改与所有正文编辑一起写盘。
- **ALT-006**：拒绝该方案，因其违反正文显式保存约束并会静默提交用户未保存内容。

## Implementation Notes

- **IMP-001**：源码历史使用组件导出的 Rope；解析器 Rope 仅在后台 UTF-8 快照边界转换，不升级 parser 依赖。
- **IMP-002**：磁盘版本使用 BLAKE3 与长度；目标旧片段还需逐字节复核。局部 FNV hash 不作为身份或磁盘保护。
- **IMP-003**：输入缓冲保留 BOM 和既有换行字节；Enter 按源中的首个换行格式插入，不规范化粘贴内容。
- **IMP-004**：实现状态和人工验收结果分别记录；未实际运行验证的行为不得标为已验证。
