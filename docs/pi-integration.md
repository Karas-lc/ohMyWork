# Pi Integration

> V1 的职责是原生界面和官方协议适配，不是再实现、治理或配置 Pi。

## 1. 保持用户环境

- 使用用户安装的 `pi --mode rpc`，Rust 监管子进程，严格 LF JSONL 通信。
- PATH 自动发现；允许用户指定路径或命令。V1 不自动扫描、配置或修改 WSL。
- 不捆绑 Pi/Node sidecar，不安装、升级、修复或改写 Pi。
- 不修改模型、认证、工具、Extensions、Skills、Prompts、keymap 或其他用户配置。
- 不由宿主定义 Agent 的默认排队、插话、工具审批等策略。
- 版本/能力不兼容时报告诊断，不偷偷禁用扩展或更换用户配置。

Pi 自身依配置读写文件、加载扩展、联网或更新会话是其运行行为；ohMyWork 不能承诺它“零副作用”。能力探测必须避免发起模型任务或试执行工具，具体方式待定。

## 2. cwd 与会话由用户选择

Workspace 只有一个，但 Pi 工作目录不绑定 Workspace、Atlas/Efforts/Archive 或项目身份。

1. 用户指定目录。
2. 用户选择新建或恢复已有 Pi 会话。
3. 以选定 cwd 启动/连接相应 RPC 运行环境。
4. 切换目录时仍由用户选择新建或恢复，不自动延续旧绑定。

旧的“每个 Workspace 永远一份会话”“每目录自动记住一份”“自动恢复最后会话”不再是要求。恢复候选发现、所选历史与 cwd 不同如何提示仍待设计；不得篡改 Pi 历史或强行换目录后声称上下文等价。

`cwd` 是运行上下文，不是沙箱。Pi 能访问哪些目录、符号链接或工具由 Pi/OS/用户配置决定，宿主不施加文件树、ignore 或 Archive 限制。

## 3. 显式上下文

侧栏提供文本输入及待附加清单：

- 用户可输入/粘贴文本。
- 从文件树、页面或选区主动选择“添加到 Pi”。
- 发送前可检查、移除，确认发送后才附加。
- **文件传路径，选区传文本**；宿主不自动读整篇文件塞入消息。
- 路径在用户指定 cwd 下必须可理解，具体消息包装待定。
- 不自动附加 Atlas、Efforts、Archive、最近页面、搜索或 Task 数据。
- Archive 默认不参与宿主汇总，不妨碍用户主动附加其中内容。

这约束宿主注入行为，不约束 Pi 自己根据消息、配置或工具去读取。用户选择发送给 Pi 的内容可能经其模型服务联网，不能因工作站本地优先而承诺模型端离线。

## 4. 界面与生命周期

- 可收起、可调宽度的 GPUI 侧栏，与正文或预览并排。
- 用户显式关闭 Pi 面板：若正在处理，先请求官方 abort，再有序关闭 RPC 进程，保留 Pi 自己的历史。
- 不实现“暂停进程后原地续跑”的承诺。
- 视觉收起、切换标签与显式关闭是否为同一操作，尚待 UI 决策；不得擅自变成常驻后台任务系统。
- select/confirm/input/editor 映射为原生 GPUI 对话控件；响应 ID、取消、超时和关闭清理遵循协议。
- 不支持的 TUI-only 能力明确诊断/降级，不伪装成功。

宿主不擅自设置 streamingBehavior、改变用户队列偏好。官方协议要求调用参数时，需要按用户显式意图适配；不得创建一套新的宿主 Agent 策略。执行期间输入 UX 的精确映射仍须对目标 Pi 版本核验。

## 5. 协议正确性（不是用户策略）

- stdout 持续读取，以 LF 分帧，接受帧末 CR；不得按 Unicode 行分隔符拆 JSON 字符串。
- stderr 独立消费，避免进程背压；日志须过滤敏感输出。
- 命令响应按 ID 关联，不假定顺序；事件与响应可交错。
- prompt 接受不等于完成；被扩展直接处理、未启动运行的请求不能永远等 settled。
- 有运行时以 `agent_settled` 表示当前自动工作结束，`agent_end` 后可能还有重试或队列工作。
- 增量消息最终以完整 message_end 为准。
- 历史通过目标版本官方能力读取，不直接改写 Pi Session 文件。
- 会话数据版本和协议能力需验证，不硬编码“所有用户都同一版本”。

未知事件可安全忽略并报告类型；未知交互请求不能无响应挂起。解码、数据限额和取消属于宿主健壮性，不是限制 Pi 工具权限。

## 6. 信任、故障与诊断

Pi 及其扩展以用户权限运行。工具执行事件不是执行前拦截机制。ohMyWork 只展示、传递明确操作和支持中止，未来宿主自动化权限不覆盖 Pi 内部工具。

异常退出只影响对应会话 UI。关闭超时、强制终止与进程树清理需实现前确定，不声称 abort 能撤回已发生的工具副作用。

诊断区分：未找到程序、不可用目录、协议不兼容、配置/认证问题、项目信任状态、协议错误和退出码。不给用户自动改配置，不记录默认完整对话、消息内容或凭证。

## 7. 验证与开放项

用假 RPC 进程测试分帧、背压、流式归约、接受/完成、取消、关闭、Extension UI、异常退出；真实 Pi 兼容验收使用明确版本，不改用户环境。

额外验证：无自动上下文、文件仅传路径、手动 cwd/历史选择、没有宿主 queue/steer 默认策略、诊断包不泄露会话内容。

未定：支持版本矩阵、Windows 命令启动/转义、历史发现、视觉收起与关闭区分、超时/强停、所有协议交互映射。只在这些边界上做必要技术研究，不重新询问或制定用户的 Pi 配置政策。
