## 1. 依据与当前事实

依据仓库的 `AGENTS.md`、`docs/product-requirements.md`、`docs/architecture.md`、`docs/pi-integration.md`、`docs/task-calendar.md`、`docs/theme-system.md`、`docs/roadmap.md` 与现行 ADR-0001/0005/0007/0008/0009/0010。ADR-0002/0003/0004 是历史，不作为实现要求。

当前仓库只有文档和 MIT LICENSE，没有 Cargo 工程、产品代码或测试基础设施。已有文档多数尚未纳入 Git，实施时不得覆盖或丢失这些文件，不自动提交。

本机只读探测结果：

- Windows 11 x64，Build 26200；Core Ultra 7 255HX，约 32 GB 内存；Intel Graphics + RTX 5070 Ti Laptop，NVMe SSD，当前 2560×1600/60 Hz。
- 当前 bash/PowerShell 均未找到 rustc/cargo/rustup，用户标准 `.cargo/bin` 也未发现 rustc/cargo。不能断言所有非标准位置都没有安装，准备阶段先确认。
- Visual Studio Build Tools 2026 已安装并具有 x64 C++ 工具组件；cl 不在当前普通 shell 的 PATH，不等于没有 MSVC。
- 当前 PATH 未找到 CMake/clang-cl；Ninja 可用。Windows SDK 和其他原生依赖必须实际验证。
- Node 可用，但不因此引入 Node sidecar、JS 前端或捆绑 Pi。

## 2. 交付范围与不可变约束

### V1 必须交付

1. Windows 11 x64 Rust/GPUI 原生应用，当前用户安装包、手动升级。
2. 唯一 Workspace，根目录 Atlas/、Efforts/、Archive/；项目/领域为普通目录；自动创建 `.ohmywork/id`。
3. LocalAppData 默认应用状态与一个全局 SQLite 派生索引；可选便携状态。
4. CommonMark + GFM 纯可视化 Markdown、Raw 保留、最小范围写回，无源码模式。
5. 正文 Ctrl+S，关闭脏内容保存/放弃/取消；不持久化未保存草稿。
6. 真正外部修改立即优先，丢弃该文件未保存编辑，无恢复机会。
7. Task 组件立即只提交任务字段，其他脏正文留在内存。
8. 基础 Task：checkbox、标题、可选 start/due 日期、priority 1–9（9 最高），无独立 status。
9. 文件树、专有 `.ohmyworkignore`、跟随链接并防循环；文件名及 Markdown 正文搜索，Archive 默认不参与搜索/任务。
10. 单主窗口、嵌套横纵 Pane、标签/滚动/布局恢复；普通可点击链接。
11. 无限画布 Homepage、内置组件和布局 JSON 导入导出。
12. 图片/PDF 只读预览，其余系统默认打开。
13. 用户现有 Pi RPC 的侧栏和原生 Extension UI；用户选 cwd、新建/恢复及附加内容，不干涉 Agent 配置/策略。
14. 手动导入 Zed 主题副本、内部 Token、关键色安全覆盖；双语、键盘与无障碍。
15. 本地日志与手动诊断导出，无遥测或自动上报。

### 明确排除

V1 不做多 Workspace 管理、项目数据库对象、Live Preview、源码模式、反向链接、重命名引用联动、日历、ICS、RRULE、任务依赖、OCR、PDF 批注、自动更新、团队协作、资源信封、自动化、插件宿主、DQL/DataviewJS。

V2/V3 方向只保留文档，不预建通用框架或接口占位实现。

### 本轮补充的 Task 覆盖决定

用户已确认：同一 Task 字段在正文缓冲区尚未保存时，Task 组件操作覆盖该字段的本地修改；其他字段和正文保持原来的未保存状态。磁盘只写本次组件意图，不提交整条任务的所有未保存变更，更不提交整篇正文。

如果 Task 身份无法确认、结构已删除或源版本发生真正外部变化，不得猜测覆盖。这些属于定位/竞争错误，不是字段优先级冲突。

M0 首先将这条决定同步到需求、Task 规格、架构及 ADR-0008，再编写测试。

## 4. 候选工程结构与依赖策略

建议最小 Cargo workspace，仅在职责已被实际用到时创建模块：

```text
Cargo.toml / Cargo.lock / rust-toolchain.toml
crates/
  omw_app/          # GPUI 启动、窗口、视图、命令、主题、双语、预览集成
  omw_document/     # 原文/源范围、编辑事务、Markdown、Task 和局部写回
  omw_local/        # 单根目录、Windows 文件读写、watcher、全局索引、应用状态
  omw_pi/           # 官方 RPC 分帧、状态、子进程与 UI 请求适配
 tests/            # 跨模块 Windows 集成夹具（实际放置遵循 Cargo 测试结构）
 fixtures/         # 人造 Markdown、主题、图片/PDF、RPC transcript
 tools/            # 测试数据生成、性能采集、文档检查
 packaging/windows/
 .github/workflows/
```

- `omw_document` 不依赖 GPUI 或真实文件系统，便于属性测试。
- `omw_local` 不导入 UI，统一管理同一文件的保存队列；应用组合服务，不让组件直接写文件。
- `omw_pi` 不依赖 Workspace 身份，输入显式 cwd、启动描述和用户操作。
- 多个 Pane 打开同一真实文件应共享文档状态，不能各自维护互相覆盖的副本。
- 不在主循环中混用阻塞 I/O；后台结果携带版本/代次，通过有界事件传回 UI。

候选库只作为 M0 评估起点：

| 职责 | 候选与决策条件 |
|---|---|
| GUI | GPUI 固定 revision/release；核验 Windows、中文 IME、焦点、可访问性；不照搬 Zed 全应用代码 |
| Markdown | pulldown-cmark、comrak 等带源位置解析能力；用保真夹具选择，不能全树序列化覆盖未改内容 |
| SQLite | rusqlite 或同等同步库放专属后台服务；验证 FTS5 与迁移，不为 UI 阻塞 |
| 搜索 | FTS5 候选；专测中文、英文、短查询和路径，不能默认英文分词器满足中文全文搜索 |
| 文件规则 | gitignore 风格 matcher，但关闭所有自动 `.gitignore`/全局 Git 规则发现 |
| 文件通知 | notify 等 + Windows 原生身份/安全替换 API，处理重复/丢失事件 |
| PDF | 优先评估可再分发的 PDFium 绑定与 x64 DLL；许可证、构建来源、内存/崩溃边界通过后锁定 |
| 图片 | Rust 图片解码库，按选定格式和内存限制启用 feature |
| RPC/JSON | serde/serde_json 与独立异步管道；运行时选择服从 GPUI 集成验证 |
| 安装包 | 首选评估 NSIS 当前用户安装；不得选择运行时必需管理员权限的配置 |

所有直接/原生/传递依赖记录许可证和安全来源；固定工具链与锁文件。无法验证 GPUI、PDF 或可访问性能力时提出具体风险，不声称已支持。

## M0. 工程准备与高风险验证

### 工作

- 检查非标准 Rust 安装位置；若缺失，说明并准备 x86_64-pc-windows-msvc 工具链，激活已有 VS 开发环境、核验 SDK/原生依赖。
- 读取所选 GPUI 的官方 Windows 文档/示例，固定可构建版本；许可证检查后建立最小可重复构建。
- 原型仅用人工夹具和临时目录，不读取或改写用户真实知识库/Pi 配置。
- 建立三个必须先验证的尖峰：
  1. GPUI 纯可视化段落/列表/Task/Raw 的选择、中文 IME 和源位置映射。
  2. 磁盘原文 B、内存脏文档 M、Task 字段操作 P 的局部提交/内存合并，含用户刚确认的字段覆盖。
  3. 图片/PDF 原生只读渲染、资源上限与分发依赖；同时检查 GPUI Windows 可访问性路径。
- 用官方 Pi 本机文档/示例静态核验所需命令和事件。无需模型请求或试运行用户工具；真假环境严格区分。
- 写技术决策/调查报告：候选、验证证据、版本、许可证、失败项、最终选择。
- 同步本轮 Task 决定到长期文档。

### 交付与退出条件

- 新机器可遵循开发文档编译最小 GPUI 窗口；不是仅 `cargo check`。
- 输入中文/选区/Raw 不改坏源片段；至少一个 Task 局部提交夹具通过。
- 不将编辑器原型称为完整 GFM 产品。
- PDF 和 Windows 可访问性有可行证据；若失败必须明确阻塞，不默认降级需求。
- `docs/development.md`、技术决策记录及 M0 测试结果完成。

### 工作

- 创建 Cargo workspace、锁定工具链、格式化/Clippy/test Windows CI。
- GPUI 主窗口、基础命令注册、焦点路由、中文/英文文本目录、基础主题 Token、本地结构化日志。

- 应用启动不启动 Pi、不扫描 Zed 主题、不自动附加内容。

### 测试/验收

- 根目录正确、ID 重启稳定、Effort 不产生项目元数据。
- `.gitignore` 的存在/内容不影响应用规则；Archive 仍可在文件树查看。

- 索引文件可删除重建，布局/设置/主题不能被连带清除。
- 临时目录测试不接触用户内容；CI 有可运行 Windows smoke test。

## M2. 文档状态与安全文件写入

### 关键状态

为每个打开文件维护磁盘基线 B、内存文档 M、源版本、dirty 状态、待提交事务。明确内容版本与 watcher 通知不是一一对应关系。

### 工作

- 建内存编辑事务、撤销/重做、源片段保留和编码/换行策略。
- 正文仅显式保存；关闭给出保存/放弃/取消；不做恢复草稿。
- 同目录临时文件写完后刷新并使用已验证的 Windows 安全替换；处理访问拒绝、杀毒锁定、磁盘满、取消等失败。
- 识别应用自身提交（目标身份/版本/内容指纹），不能用“忽略接下来 N 毫秒事件”吞掉真实外部修改。
- 真正外部改变立即重载，清除该文档本地未保存内容及可恢复它的撤销历史；不污染其他文档。
- 同文件写操作串行并版本校验；跨进程的竞态边界记录清楚，不把普通 rename 宣称为绝对 CAS。

### Task 专项事务

1. 组件携带目标 Task 的可校验定位与“只改字段 X”的明确意图。
2. 在磁盘基线 B 上生成最小变更 P；磁盘写入 B+P，不能序列化 M 全文。
3. 成功后把 P 合并到 M：该 Task 的字段 X 以组件为准，其他脏字段和正文保留。
4. 保持正确的 dirty 判定与后续 Ctrl+S 行为，不能后续保存把已提交字段回滚。
5. 无法可靠定位或外部版本改变时先遵循外部优先/错误报告；禁止猜同标题行。

### 测试/验收

- 正文未保存 + Task priority 从脏值 2 改到 9：磁盘只含 priority=9，其他正文原样；内存保留无关编辑。
- 不同字段/多 Task/跨 Pane、任务删除/移动、重复标题、UTF-8/CRLF、嵌套列表。
- watcher 自写回声、外部与自写交错、删除/重建、保存失败和重试。
- 故障注入下无半文件；不生成永久 `.bak` 或未保存草稿。
- 核心事务无 GPUI 依赖，纯测试可稳定重放。

## M3. 可视化 Markdown 编辑闭环

### 工作

- 实现 CommonMark/GFM 的可视化节点：段落、标题、强调、列表/Task、引用、代码块、表格、分隔线、普通链接/图片等；建立明确兼容语料。
- 语法解析不等于编辑支持，逐节点测试光标、选择、跨块删除、粘贴、撤销与 IME。
- Raw 节点显示类型/原始内容，可移动或删除，不能直接编辑内部，也不执行 HTML 脚本。
- 未编辑字节尽量保持；对受影响结构最小重新序列化，不自动格式化全文。
- 接入 M2 的 Ctrl+S/关闭/外部优先保存流程。
- 相对文件与根路径链接、HTTP/HTTPS 外部打开；无 backlink/slug/重命名改写。

### 测试/验收

- 打开 → 无修改 → 保存应字节不变；单节点编辑不改写无关段落/未知字段。
- GFM 表格、引用/嵌套列表、代码、混合中英文、Emoji、组合字符、Raw 内容语料。
- 纯可视化路径完整，没有用“切换源码修复”充当验收兜底。
- 多视图共享文档，当前选择/焦点不导致内容副本分叉。
- 用户能完成“打开 Effort 笔记 → 可视化编辑 → Ctrl+S → 外部编辑器验证”。

## M4. 全局索引、搜索与基础 Task

### 工作

- 文档变化增量解析并更新一个全局 SQLite 索引，使用后台任务/事务与代次，限制并发和积压。
- 文件名/路径、标题、Markdown 文本查询与片段；默认排除 Archive，可显式纳入；不搜索 PDF/OCR。
- 专门验证中文和一/二字符查询；选定 FTS/tokenizer/短查询策略后再承诺结果完整性。
- Task checkbox、标题、start/due 日期、priority 1–9，9 最高；未知字段不赋行为。
- Task 列表汇总/定位/即时编辑接入 M2；不引入 Task UID 或独立权威数据库。
- 建索引重建、丢失文件、规则改变、重复通知和中断恢复流程。

### 测试/验收

- 手工标注语料得到预期中文/英文结果，不仅测速度不测召回。
- 删除索引后重建恢复一致内容，用户状态不丢。
- Task 未设置字段不被补写；9 高于1，无独立 status/日历。
- Archive 默认排除和显式纳入一致，ignore 调整后查询反映最新内容。
- 一万篇/两万 Task 基准首次运行，记录差距并修复，不能全部推迟到发布前。

## M5. Pi 侧栏与官方 RPC

### 工作

- PATH 发现、显式启动描述、Windows `.cmd`/可执行文件/参数/空格路径的安全处理；不随意经 shell 拼接文本。
- 用户选 cwd、新建/恢复，目标目录不强制位于 Workspace；旧目录和选定历史不一致如何呈现需先确认。
- 官方 LF JSONL、CRLF、UTF-8 分块、响应 ID、持续 stdout/stderr、背压和有界 UI 消费。
- 正确区分 accepted/handled/queued、agent_end/agent_settled、message delta/最终 message。
- 展示用户消息和活动；不要建立宿主自己的 Agent 队列/steer 政策，不改 Pi 设置。
- 文件传路径、选区传文本的待发清单，确认发送；不得隐式读整库或把元数据插入 system prompt。
- select/confirm/input/editor 的 GPUI 控件、取消、超时和关闭清理。
- 用户关闭面板先 abort 再有序退出；超时与强停需明确，不能声称回滚已执行工具。

### 测试/验收

- 自制假 RPC 进程覆盖分片/超长/非法帧、事件与响应交错、stderr 压力、未知事件、UI 请求、异常退出和关闭。
- 消息不启动运行时不会永久等 settled；未知交互不会无响应挂起。
- 明确选择的内容之外没有附加字段/文档；对话正文不进入普通日志。
- 单独在用户授权的真实环境确认最低兼容版本，不安装、升级或覆写用户 Pi。
- 默认不启动背景 Agent，不因宿主 ignore/Archive 设置限制 Pi 文件访问。

## M6. 工作台布局、无限画布、预览与个性化

### Pane 与 Homepage

- 嵌套横纵分栏、标签移动、键盘焦点与最小可操作尺寸。
- 恢复 Pane/标签/滚动/选中项；缺失文件为可关闭占位；不恢复未保存编辑。
- 无限画布逻辑坐标、平移缩放、自由摆放/尺寸调整、可见区域裁剪、键盘定位、适合全部内容。
- 起始布局含内容入口、最近/置顶页面、基础 Task、Pi 状态/会话、快捷动作，可删除。
- 内部布局为权威，JSON 导入验证后提交，保留当前可用布局直到成功；无插件组件系统。

### 只读预览

- 实现 M0 通过的图片格式/PDF 渲染路线，可见页按需解码/栅格化，缓存有界。
- 大图/多页文档、畸形输入、损坏/密码文件、关闭取消、缩放/高 DPI 需确定可用反馈。
- 无编辑、批注、OCR；其他文件调用系统默认程序。

### 主题/快捷键/语言

- 手动导入 Zed JSON 原始副本到 LocalAppData，无扫描/来源热监听。
- 语义映射、缺失回退、关键对比度自动修正清单、预览/取消/安全主题恢复。
- keymap.jsonc 覆盖宿主命令，界面显示最终绑定，错误配置保留有效状态；冲突/重载规则先定，不做键位编辑器。
- 中文/英文可切换，不改分区名、不翻译 Pi 输出；键盘、可访问名称和缩放在组件中落实。

### 测试/验收

- 画布/Pane 序列化往返，恶意/损坏布局不导致失去操作入口。
- 手动导入后删除原主题文件仍可用；安全覆盖只改内部 Token。
- 大 PDF/图片不冻结输入，缓存不无界增长；真实依赖与安装包可再分发。
- 双语、IME、焦点、屏幕阅读路径、缩放和减少动态效果逐项记录。

## M7. Windows 分发、诊断与发布门槛

### 工作

- 生成 per-user Windows 11 x64 安装包，快捷方式、卸载、手动升级；无需管理员权限、没有自动更新服务。
- 管理 GPUI/PDF 等原生资源和运行库；签名证书/签名发布能力需实证，不承诺“无 SmartScreen 提示”。
- 升级先迁移/备份应用持久状态，索引可重建；卸载不删除 Workspace。应用数据保留/清除 UX 实施前确认。
- 本地日志轮转、诊断白名单导出，脱敏路径/命令/错误，默认无正文、Pi transcript 或凭据；无 telemetry。
- 合并端到端流程、长时间运行、故障注入、无障碍和性能结果。
- 更新 README、开发/安装/诊断文档和发布清单，明确已实现/未支持范围。

### 退出条件

- 标准非管理员用户可安装、运行、手动升级、卸载，Workspace 内容完整。
- 离线核心工作台可用；Pi 未安装时核心功能仍正常。
- 所有 V1 需求有对应自动/手动证据；没有以 V2/V3 预留工作替代 V1 完成。
- 性能和可访问性达到约定门槛；没有未处置的数据写错/用户配置被修改等阻塞问题。

## 6. 测试与性能方法

### 分层测试

- 纯逻辑：Markdown/Raw、Task、字段 patch、布局坐标和主题映射单元/属性测试。
- Windows 文件集成：临时目录、中文/长路径、权限/锁定/链接、外部修改、临时替换、自写去重。
- 协议：假 Pi 子进程，无 API key/真实模型依赖。
- UI：组件状态、键盘/焦点、中文 IME；可自动化部分进 CI，其余有带版本的手工检查表。
- 分发：Windows 11 标准用户环境，签名/运行库/原生 DLL/升级/卸载 smoke test。

### 预期日常命令（工程建立后）

```text
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo build --release --locked --target x86_64-pc-windows-msvc
```

具体 UI/原生依赖若有专用测试 target，M0 固定命令并写开发文档，不用跳过测试来维持绿色 CI。依赖漏洞/许可证扫描和安装包 smoke test 加入发布流水线。

### 性能验收

批准预算：启动到可交互 P95≤2秒；索引就绪搜索首批 P95≤100ms；普通页面输入到显示 P95≤50ms；稳态应用私有内存≤500MiB。

M0 固定可复现方法，建议：

- 使用固定 seed 的一万篇约200MB、两万 Task 语料，含中文/英文、分区和普通大文件；不使用私有笔记。
- 启动从进程创建计时，到窗口真正接受输入且主要框架可用；索引仍在后台时独立标记其状态。冷/热分开报告，不混合样本。
- 搜索从提交查询到首批结果可显示，包括应用 debounce/排队，不只统计 SQL。
- 输入指标覆盖事件入队至实际帧呈现；若只能采集布局时间须声明代理指标，不能冒充端到端。
- 固定普通页面大小、打开标签/画布组件数量、采样次数与 P95 算法；记录 Windows、GPU、驱动、供电、DPI、分辨率和所在盘。
- 内存明确使用进程私有内存而非工作集；Pi、GPU 显存、PDF附加进程（若有）另报，总体占用同时透明报告，不能靠移出进程隐藏成本。
- 首次索引耗时、大文件与预览压力单列，不能以未进入主预算为由无限占资源。
