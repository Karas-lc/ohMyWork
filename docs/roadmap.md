# Roadmap

> 当前阶段仍为规格收敛与文档同步。下列是后续实施切片，不表示本次已批准启动代码开发。

## V1：本地工作台基础

### 0. 规格与可行性

- 以一个 Workspace 和 Atlas/Efforts/Archive 替代多 Vault 架构。
- 选定 GPUI 可视化编辑、Raw 节点和最小源范围写回方案。
- 验证 Task 局部提交与脏正文共存、自写事件识别和 Windows 原子替换。
- 验证图片/PDF 只读预览方案及许可证、内存成本。
- 核验 Pi RPC 必要能力，不干涉其配置。
- 固定性能测试方法、无障碍验证和安装策略。

退出条件：阻塞当前切片的问题已决；不得为了 V3 建完整日历引擎。

### 1. 主窗口与内容目录

- Windows 11 x64 Rust/GPUI 工程及 CI。
- 唯一 Workspace、三个真实分区、最小 `.ohmywork/id`。
- LocalAppData 应用数据、一个全局 SQLite 派生索引。
- 文件树、`.ohmyworkignore`、链接目录跟随与循环检测。
- 标准命令与嵌套 Pane/标签骨架。

验收：原地使用文件，不要求项目对象；Archive 默认搜索/任务排除；不使用 `.gitignore`。

### 2. 可视化 Markdown 与基础 Task

- CommonMark/GFM 纯可视化，Raw 保留，无源码模式。
- Ctrl+S、保存/放弃/取消、无崩溃草稿恢复。
- 外部优先直接替换，任务组件只提交任务范围。
- checkbox + start/due 日期 + priority 1–9（9 最高）。
- 文件名/Markdown 正文搜索和普通可点击链接。

验收：未编辑源片段保留；Task 操作不提交无关正文；外部版本丢弃行为与文档一致；不做引用图或自动更新链接。

### 3. Pi 原生侧栏

- PATH + 显式路径/命令，用户自行指定 cwd。
- 用户选择新建/恢复，无唯一 Workspace Session 绑定。
- 原生 Extension UI、状态展示、用户关闭时 abort/有序退出。
- 显式上下文清单，文件路径/选区文本。

验收：不修改用户配置，不自动灌入知识库，不定义宿主 Agent 队列/插话政策；以假进程和选定官方版本核验协议。

### 4. 主页、预览与个性化

- 无限画布 Homepage，平移/缩放、键盘定位和可删除起始布局。
- 内置内容入口、最近/置顶页面、基础任务、Pi 状态/会话、快捷动作。
- 界面维护布局、版本化 JSON 导入导出；恢复标签/Pane/滚动位置，不恢复脏正文。
- 图片/PDF 只读预览，其余系统打开。
- 手动导入主题原始副本、语义适配和关键安全覆盖。
- 简体中文/英文、默认键位 + keymap.jsonc。

验收：无 Calendar 组件，不因画布引入插件宿主；预览不支持编辑、批注或 OCR。

### 5. Windows 分发与验收

- 当前用户安装包、快捷方式、卸载、手动升级，无自动更新。
- 本地日志、用户主动导出且默认不含内容/凭据，无遥测。
- 数据迁移/索引重建、文件失败与进程异常测试。
- 无障碍、双语、输入法、缩放和长期运行。
- 基准机上一万篇约 200 MB Markdown、两万条 Task：启动 P95 ≤2 秒、搜索首批 P95 ≤100 ms、输入显示 P95 ≤50 ms、稳态私有内存 ≤500 MiB。

验收按 [产品需求](product-requirements.md)，首次索引、Pi 与 GPU 资源单列。以上数值为目标，不是已测成绩。

## V2：连接与自动化

- 独立进程插件，官方 Rust 优先，协议语言无关；只扩展数据/能力，宿主渲染 UI。
- 浏览器、邮箱、微信、飞书等连接器聚合/调度，不替代客户端。
- 全局资源信封 + 原始载荷，开放、传输无关 JSON 契约。
- `.ohmywork/rules/*.rule.jsonc`、分级授权、输入快照和执行日志。
- Dataview 功能级兼容：元数据、TABLE/LIST/TASK/CALENDAR 查询、DQL/内联 DQL、主要 dv/dv.io API；不承诺 Obsidian app、DOM 或其他插件。

`CALENDAR` 查询类型是此前 Dataview 兼容目标的一部分，但不得据此提前交付 V3 日历产品；具体查询渲染范围需在 V2 兼容矩阵中协调并说明差异。

旧多 Workspace 资源引用关系不照搬；未来资源如何归入普通 Effort 文件夹需重新设计。插件/自动化协议尚不冻结。

## V3：日历与交换

日历与 ICS 导入导出放在 V3；重复、依赖、时区和标准映射届时按实际需求评审。V1 不承诺 iCalendar 原生模型或无损往返，也不为未来规则增加复杂字段。

priority 9 最高与 iCalendar 数值方向不同；如未来交换，需要显式转换与迁移，不得改变既有 Markdown 的含义。
